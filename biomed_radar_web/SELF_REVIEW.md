# Web 工作台自审记录

## 设计判断

本版本定位为内容运营工作台。用户每天进入页面时，最重要的不是被介绍项目背景，而是快速完成四件事：看候选、判质量、编日报、收反馈。因此页面采用顶部导航、主候选列表、详情面板、日报预览和反馈权重，而不是作品集式长页面。

## 已通过

- 页面标题和文案不出现具体公司品牌，适合作为通用作品项目展示前的产品原型。
- 视觉结构从大块卡片改为工作台式分栏，候选资讯以紧凑列表呈现。
- 样例内容聚焦国内创新药产业事件，弱化泛科研和会议趋势稿。
- 每条需核验资讯都写明核验原因，避免“需核验”成为空标签。
- 反馈机制改为单条轻量选择，未来可扩展为批量反馈和异常反馈识别。
- 前端没有写入邮箱、授权码、密钥、真实收件人等敏感信息。
- 已撤掉 AI 生成的科技雷达图片，避免视觉方向偏“炫技展示”。
- 页面重心回到候选筛选、详情核验、日报生成和反馈复盘。

## 仍需继续迭代

- 当前数据仍是演示样例，下一步需要接入本地数据库或 Python 输出的 JSON。
- 反馈目前保存在浏览器本地，真实上线需要接入后端存储。
- 原文链接当前使用占位链接，接入真实检索后必须替换为可直接打开的原始页面。
- 还没有账号权限、多人反馈合并、反馈可信度评分等机制。

## 下一版建议

1. 使用 SQLite 保存候选资讯、日报批次、反馈记录和来源权重。
2. Python 检索任务每天写入数据库，网页只负责运营筛选和审核。
3. 邮件中的反馈按钮跳转到网页的当期反馈页，用户一次性完成多条评价。
4. 管理端增加“规则学习记录”，展示哪些反馈改变了来源和主题权重。
