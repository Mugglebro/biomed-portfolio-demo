# 生物医药产业资讯雷达 Web 产品原型蓝图

## 1. 产品定位

本产品不是资讯展示网站，也不是作品集页面，而是一个面向内容运营人员的产业资讯工作台。

它解决的问题是：每天有大量生物医药资讯，但运营人员真正需要的是可验证、可筛选、可编排、可复盘的高质量产业事件。

## 2. 目标用户

主要用户：内容运营、产品运营、行业研究助理。

使用场景：

- 每天上午查看自动检索结果。
- 快速判断哪些资讯值得推送。
- 对高风险信息进行人工核验。
- 生成内部日报或邮件简报。
- 收集收件人的反馈，用于优化下一轮筛选规则。

## 3. 核心问题

### 信息过载

公开来源分散，人工逐个查找容易遗漏，也容易重复看到同一事件的多篇转述。

### 质量不稳

二次报道、会议稿、趋势解读容易混入候选池，但运营需要的是明确发生的产业事件。

### 核验断层

审批、临床、融资、授权金额、上市公司公告都属于高风险事实，不能只依赖转载标题。

### 反馈难沉淀

过去收件人是否认可某条资讯，往往停留在口头反馈或邮件回复里，无法进入规则迭代。

## 4. 产品目标

第一阶段目标：让运营人员能在一个网页中完成“筛选、审核、编排、反馈”的闭环。

不是追求自动判断事实，而是把自动化用于降低重复劳动，把最终判断权留给人。

## 5. 当前内容偏好

优先关注：

- 中国创新药
- NMPA / CDE
- BD / 授权 / 出海
- 融资并购
- ADC / 双抗 / 细胞治疗等产业事件
- 商业化 / 医保 / 集采
- 上市公司公告

默认降权：

- 泛科研论文
- 基础生物医学研究
- 会议论坛
- 白皮书
- 单纯趋势解读
- 无明确事件的新闻稿

## 6. MVP 功能范围

### 候选池

- 展示自动检索后的候选资讯。
- 支持分类筛选、关键词搜索、只看需核验。
- 展示标题、来源、日期、类别、评分、状态。

### 审核详情

- 展示摘要、推荐理由、核验原因、原文链接。
- 明确告诉运营人员为什么某条内容需要人工核验。
- 支持反馈：重点关注、可做选题、无需关注。

### 日报编排

- 支持将候选资讯加入日报。
- 实时生成日报文本预览。
- 后续可扩展 HTML 邮件预览、附件 Excel、发送记录。

### 反馈学习

- 记录用户对资讯的偏好。
- 将反馈转化为主题权重、来源权重和降权规则。
- 异常反馈进入人工复核，不直接污染规则。

## 7. 关键页面

### 首页即工作台

用户打开页面后不进入宣传页，而是直接看到当天候选资讯和审核状态。

页面结构：

- 左侧导航：候选审核、日报编排、反馈学习、产品自审。
- 顶部状态：候选数量、入选日报、规则版本、结构字段。
- 来源策略：展示系统更信任哪些来源。
- 候选列表：核心工作区。
- 右侧详情：显示当前选中资讯的核验信息。
- 底部区域：日报草稿和反馈权重。

## 8. 产品判断原则

- 原始来源优先于二次转述。
- 明确事件优先于趋势判断。
- 国内产业事件优先于泛科研动态。
- 高风险事实必须标记核验原因。
- 用户反馈影响权重，但不替代运营判断。
- 页面首先服务日常操作，其次才服务作品集展示。

## 9. 后续版本路线

### V1 静态交互原型

目标：验证产品流程是否成立。

当前状态：已完成。

### V2 本地真实数据版

目标：由 Python 检索脚本输出 JSON，网页读取真实候选数据。

新增能力：

- 读取当日真实候选。
- 展示真实原文链接。
- 导出当日日报草稿。

### V3 数据库版

目标：用 SQLite 替代 Excel 作为核心存储。

新增数据表：

- news_items：资讯候选。
- digest_batches：日报批次。
- digest_items：日报条目。
- feedback_records：反馈记录。
- source_rules：来源权重。
- topic_rules：主题权重。

### V4 本地 Web 服务版

目标：用 Flask 或 FastAPI 提供本地网页服务。

新增能力：

- 保存用户操作。
- 批量加入日报。
- 反馈写入数据库。
- 查询历史日报。

### V5 在线脱敏演示版

目标：放入求职作品集。

要求：

- 只展示脱敏样例数据。
- 不暴露邮箱、授权码、真实收件人。
- 不展示内部业务数据。
- 重点呈现产品思考和运营流程。
